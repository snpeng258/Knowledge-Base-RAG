# Code Review 检查清单

> Created: 2026-08-20
> Updated: 2026-08-20
>
> 本文档是 `AGENTS.md` 中「When Reviewing Code」的完整版。
> 进行 review 或自我审查时按本清单逐项检查。
>
> 已删除与本仓库无关的 Next.js 16 / EdgeOne Pages 专项条款。栈选定后，把栈相关检查追加为新节，不要改写通用节的含义。

## 文件组织与职责

- 过长文件/函数是否未按职责拆分（看职责混杂与自然接缝，不看行数本身）
- 是否把单模块专用代码错误提升到共享层；或把跨模块领域逻辑仍散落各处
- 文档是否放对分类：方向/方案 → `docs/designs/`；规格 → `docs/specs/`；协作与编码规范 → `docs/conventions/`

## 范围与架构纪律

- 本次改动是否偷偷选定了未决策的技术栈、目录骨架或部署平台
- 是否把 demo-init 的框架规则（App Router、`output: 'export'`、EdgeOne 字段）带进本仓库
- 是否超出 issue / 任务范围的重构

## 正确性

- 失败路径是否有明确错误信息
- 检索/入库相关改动是否仍能「回到原文」或保留 source 引用
- 公开接口变更是否有文档或 changelog

## 安全与数据边界

- 是否出现密钥、`.env`、凭据
- 是否把大于 25 MB 的文件或原始音视频加入版本库
- 是否涉及聊天记录非官方导出、解密或实时爬取

## 调试隔离

- 调试/原型代码是否被正式路径 import
- 生产环境是否仍能打到调试入口

## 协作

- Commit / PR 描述是否符合 Conventional Commits
- 需要人类决策的问题是否留在 PR 说明里，而不是用默认实现顶上
