   JSON 与本地同契约；人类路径 search 无 snippet，get 直接打 JSON。Agent 用 `--json`。要补回：复用 `formatSearchHuman` / `formatGetHuman`。

   hybrid 在截断处可能对近并列换序。一致性断言用 `--limit 50` 比 id 集合。不要把 top-10 顺序写进验收。

   对内网共享密钥可接受。若以后对团队暴露，改成稳定错误码。

## 推进机制该改什么

对照 `docs/plans/night-run-prompt.md` / `plan-loop-engineering.md`：

1. **Loop 收尾四件事要写成不可拆。**  
   #22 代码与测试通过后，commit 已在本地，但 push / issue comment / close 被上下文压缩打断，GitHub 一度仍显示「未实现」。提示词应写明：没 push、没 comment、没改 issue 状态，就不算到达终态。

2. **Windows 集成测试两条硬规则应写进自愈白名单。**  
   - 同一进程 `listen` HTTP 再 `spawnSync` 打该端口会死锁，必须 async `spawn`。  
   - CLI 子进程偶发 `0xC0000409`，复跑常过，不要为此大改。

3. **MCP / JSON-RPC 禁止经 `pnpm kb` 启动。**  
   pnpm 会往 stdout 掺字。文档已写；提示词可加一句，避免下一轮再踩。

4. **MCP `connect()` 立刻 resolve。**  
   必须等到 stdin close 再 `process.exit`，否则宿主一连上就把进程杀掉。

5. **向量测试隔离。**  
   mock embed 禁止复用生产 `modelName`（尤其 `BAAI/bge-m3`），禁止 `embedMissingChunks` 给全库灌 dummy。这比「评测挂了就改 expect」更便宜。

6. **`gh` 中文必须 `--body-file`。**  
   本机 PS 5.1 + GB2312：命令行传中文会坏，文件传是对的。控制台乱码不要「修」远端数据。

7. **侦察 sub-agent 对「已有实现」要强制对照验收命令。**  
   几次是主线自己摸到死锁 / strip-types parameter properties 才改过来。阶段 1 可要求回报「用哪条验收命令会失败」。

8. **加厚层 2 轮熔断够用；关键路径 4 轮也够。**  
   没碰到轮次不够。不要为打磨一个 issue 加轮次。

9. **依赖坍塌条款有效但今晚没触发。**  
   Postgres / TEI CPU 可用。GPU TEI 按 ADR 未启用。Ollama 离线时读路径按设计降级。

10. **不要为夜跑开合 `main` 的 PR。**  
    与 `/agents:issue-to-pr` 的「默认完成态是 PR」冲突。无人值守提示词应写明：夜跑覆盖为「线性提交到夜间分支」，早上再开 PR。否则代理会在 Ask first 的 push/PR 上自我打架。

未改 `night-run-prompt.md` 正文：把上述当作下一次修订的输入，避免夜跑自己改规则。

## 本机怎么用（收工状态）

```powershell
docker compose up -d
pnpm db:migrate
pnpm kb doctor
pnpm kb search "产品力"
pnpm kb get <id>
```

远程只读（需先设 `KB_API_TOKEN`，再 `pnpm api`）：

```powershell
$env:KB_REMOTE_URL = "http://127.0.0.1:8787"
$env:KB_REMOTE_TOKEN = "<same as KB_API_TOKEN>"
$env:KB_DATABASE_URL = ""
pnpm kb search "产品力" --json
```

MCP：用 `node --experimental-strip-types ./apps/cli/src/index.ts mcp`，不要 `pnpm kb mcp`。
